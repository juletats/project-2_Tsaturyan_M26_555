## Управление таблицами

Примитивная база данных поддерживает создание, просмотр и удаление таблиц с сохранением метаданных в JSON.

### Команды

| Команда                                         | Описание                                            |
|-------------------------------------------------|-----------------------------------------------------|
| `create_table <имя_таблицы> <столбец1:тип> ...` | создать таблицу, автоматически добавляется `ID:int` |
| `list_tables`                                   | показать список всех таблиц                         |
| `drop_table <имя>`                              | удалить таблицу                                     |
| `exit`                                          | выйти из программы                                  |
| `help`                                          | справочная информация                               |

### CRUD-операции с данными

| Команда                                                                        | Описание                       |
|--------------------------------------------------------------------------------|--------------------------------|
| `insert into <имя_таблицы> values (..) `                                       | создать запись                 |
| `select from <имя_таблицы> where <столбец> = <значение>`                       | прочитать записи по условию    |
| `select from <имя_таблицы>`                                                    | прочитать все записи           |
| `update <имя_таблицы> set <столбец> = <значение> where <столбец> = <значение>` | обновить запись по условию     |
| `delete from <имя_таблицы> where <столбец> = <значение>`                       | удалить записи по условию      |
| `info <имя_таблицы>`                                                           | информация о структуре таблицы |

### Поддерживаемые типы данных

- `int` — целое число
- `str` — строка
- `bool` — логическое значение

## Декораторы

Служебная логика вынесена из функций ядра в декораторы (`decorators.py`).

Централизованная обработка ошибок — `handle_db_errors`

Оборачивает вызов в `try...except` и печатает сообщение, возвращая `None`. Применён ко всем функциям `core.py`,
поэтому отдельные блоки `try...except` из ядра удалены.

| Исключение        | Сообщение                                                             |
|-------------------|-----------------------------------------------------------------------|
| `FileNotFoundError` | `Ошибка: Файл данных не найден. Возможно, база данных не инициализирована.` |
| `KeyError`        | `Ошибка: Таблица или столбец <ключ> не найден.`                          |
| `ValueError`      | `Ошибка валидации: <причина>`                                            |
| прочее            | `Произошла непредвиденная ошибка: <причина>`                             |

```
>>> Введите команду: create_table bad badcol:float
Ошибка валидации: неизвестный тип данных 'float'
>>> Введите команду: insert into users values ("Sergei", "abc", true)
Ошибка валидации: abc не может быть преобразовано в int
```

### Подтверждение опасных операций — `confirm_action(action_name)`

Фабрика декораторов. Перед выполнением функции запрашивает подтверждение; если введено не `y`, операция отменяется.
Применён к `drop_table` и `delete`.

```
>>> Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: n
Операция отменена.
```

Подтверждение запрашивается только если есть что удалять: при пустой таблице или отсутствии совпадений выводится
`Записи не найдены.` без запроса.

### Замер времени выполнения — `log_time`

Печатает `Функция <имя> выполнилась за X.XXX секунд.` (через `time.monotonic()`). Применён к операциям,
работающим с файлами: `insert` и `select`.

### Кэширование результатов — `create_cacher()`

Функция с замыканием: возвращает `cache_result(key, value_func)`, хранящую словарь-кэш внутри замыкания.
При повторном вызове с тем же ключом значение берётся из кэша, иначе вычисляется `value_func`.

Подключено к `select`: ключом служит пара (имя таблицы, условие `where`), поэтому повторяющиеся запросы
не вычисляются заново — в выводе пропадает строка замера времени:

```
>>> Введите команду: select from users
Функция select выполнилась за 0.000 секунд.
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+
>>> Введите команду: select from users
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei |  28 |    True   |
+----+--------+-----+-----------+
```

Кэш сбрасывается после любой записи (`insert`, `update`, `delete`, `drop_table`), поэтому устаревшие данные
не возвращаются.

Файлы `db_meta.json` и директория `data/` создаются во время работы и добавлены в `.gitignore` — в репозитории их нет.
Их можно удалить в любой момент: база данных создаст файлы заново при следующем использовании.

### Установка и запуск

Проект использует [uv](https://docs.astral.sh/uv/). Доступны цели `make`:

```bash
make install   # установить зависимости (uv sync)
make lint      # проверить стиль кода (ruff)
make format    # проверить стиль с автоисправлением
make run       # запустить базу данных
make build     # собрать пакет (wheel и sdist)
make clean     # удалить артефакты сборки и __pycache__
```

То же самое без `make`:

```bash
uv sync                # установка зависимостей
uv run ruff check .    # линтер
uv build               # сборка пакета
uv run database        # запуск базы данных
```

После установки пакета командой `pip install dist/primitive_db-0.1.0-py3-none-any.whl`
база данных запускается консольной командой `database`.

### Архитектура

- `constants.py` — константы: пути хранилища, схема таблицы, текст меню
- `core.py` — логика управления таблицами и CRUD-операциями
- `decorators.py` — `handle_db_errors`, `confirm_action`, `log_time`, `create_cacher`
- `engine.py` — основной цикл, парсинг команд, ввод/вывод
- `parser.py` — разбор условий `where`/`set` и списка значений
- `utils.py` — загрузка и сохранение метаданных и данных таблиц
- `main.py` — точка входа

### Метаданные

Структура таблиц хранится в файле `db_meta.json`:

```json
{
  "users": {
    "columns": {
      "ID": "int",
      "name": "str",
      "age": "int",
      "is_active": "bool"
    }
  }
}
```

### Данные таблиц

Данные каждой таблицы хранятся в отдельном JSON-файле в директории `data/`. Например, для таблицы `users` — файл
`data/users.json`:

```json
[
  {
    "ID": 1,
    "name": "Sergei",
    "age": 28,
    "is_active": true
  }
]
```
